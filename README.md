# 5C-CR

泊床 · 5C／5D 病床管理系統

病房排床互動網頁，使用原生 JavaScript 與 Node.js，無執行期外部相依套件。

## 執行

Node.js 24（目前已驗證）。在專案目錄執行 `npm start`，預設連接埠 3000，可透過 `PORT` 調整。`npm test` 執行排床規則測試。

## 功能

- 病房實況／預入病人兩分頁，5C 30 床、5D 32 床，採提供的正式床號與價格。
- 日期可向前／向後切換，向右捲動自動增加日期。
- 從住院任一天拖曳，整段住院期間一起移動；禁止覆蓋其他病人。
- 出院前一天綠色，出院當天不占床。
- 預入名單直接編輯、刪除，依日期排序；拖曳把手交換兩位病人入院日期，保持住院天數並檢查衝突。
- 貼上文字以空白行分隔病人。標籤支援姓名、日期／入院日期、出院日期、病歷號、診斷、目的／處置、主治醫師、意願。未提供出院日暫估四晚，必須人工確認。
- 所有新病人進入虛擬床；自動填床依日期與價格意願順序尋找整段可用床位，無法安排時保留虛擬床。原有實體床安排不會被重新分配。
- 每日各價格空床數、兩病房占床率與新入院人數比較。

## 尚待定義

(I)、(IC) 床位已保留標記；在隔離規則確認前，自動填床會略過這些床位，仍可手動安排。目前未實作臨床隔離相容性或其他尚未提供的警示規則。

文字辨識與排床為本機規則，不是外部 AI 推論。未串接模型、醫院系統、多人同步或伺服器資料庫。

資料僅保存在目前瀏覽器 localStorage，清除瀏覽器資料會遺失；此原型無登入與存取控管，請僅使用虛構資料測試，尚不適合正式病人資料。

## GitHub Pages 部署（不需要安裝 Node.js）

這是一個靜態網站：`index.html`、`style.css`、`app.js`、`logic.js` 就能運作。Node.js 只用於本機開發伺服器與測試，GitHub Pages 不需要執行 `npm start`，也不需要建置指令。所有網頁資源使用相對路徑，支援 `/5C-CR/` 子目錄。`.nojekyll` 讓 Pages 直接提供靜態檔案。

1. 在 GitHub 開啟部署 Pull Request，檢查 **Files changed**。按 **Merge pull request → Confirm merge**，將變更合併至 `main`。若儲存庫設有分支保護，先完成要求的審核與檢查。
2. 在儲存庫開啟 **Settings → Pages → Build and deployment**。
3. **Source** 選 **Deploy from a branch**。
4. **Branch** 選 `main`，資料夾選 **/ (root)**，按 **Save**。
5. 等待 GitHub 的 Pages 部署完成，可在 **Actions** 查看結果，再從 **Settings → Pages** 開啟網站。預期網址為 `https://sheep0yang.github.io/5C-CR/`，以 GitHub 實際顯示的網址為準。

網站發布不會上傳瀏覽器 localStorage 裡的名單；每個瀏覽器都有各自的資料。程式碼內只有虛構 DEMO 病人，不含真實病人資料或密碼。請勿在公開網站輸入真實病人資料。GitHub Pages 是否可用取決於儲存庫可見性、方案與組織政策。

### 子目錄部署驗證

`npm test` 包含靜態部署檢查：以 `/5C-CR/` 提供靜態檔案，確認首頁、CSS、JavaScript 與相對模組匯入成功回應。互動排床規則另有獨立測試。
